# Notes Planner — стан проекту (для нового чату з Claude)

Це файл-довідка, щоб продовжити роботу над проектом у новій розмові з Claude без втрати контексту. Встав посилання на цей файл або скопіюй його вміст на початку нового чату.

## Що це за проект

Особистий застосунок для нотаток і планування подій у календарі. Перший повноцінний проект користувача "з нуля" — навчальний, робиться крок за кроком.

- **Користувач:** новачок, вчить фронтенд/бекенд вперше. Знає HTML/CSS/JS-основи, вивчає складніші речі (JS backend, DOM-маніпуляції, git) поступово, крок за кроком, у процесі побудови цього проекту.
- **GitHub:** `Volodymyr1006/Notes-Planner` (приватний репозиторій)
- **Стек:** чистий HTML/CSS/JS (без фреймворків) на фронтенді, Node.js + Express на бекенді. Дані поки зберігаються в `localStorage` браузера (SQLite заплановано, ще не підключено).

## Як ми працюємо (важливо для нового чату!)

- **Пояснення прості, короткі, покроково.** Не перевантажувати текстом.
- **Нова функціональність (нові сторінки/фічі):** Claude веде, пропонує наступний крок, користувач підтверджує/виконує.
- **Стилізація вже готового:** користувач каже що саме змінити, Claude робить.
- **JS користувач пише сам** невеликими шматками для нового навчального матеріалу — Claude дає код + пояснення. Але коли йдеться про адаптацію готового макету/дизайну (як було з переробкою кабінету, Глосарієм і сторінкою входу) — Claude пише код повністю сам, це окремий режим роботи, не суперечить попередньому пункту.
- **Формат пояснення JS-коду:** розбір по частинах, коротко на кожен рядок/елемент, і показати відповідний фрагмент HTML.
- **Перед новим складним поняттям** — питати, чи пояснювати, чи одразу писати код.
- **Не забігати наперед:** не починати наступне завдання чи ставити уточнювальні питання про нього одразу після завершення поточного — чекати, поки користувач сам підніме тему.
- **Коміти й коментарі в коді — лише англійською.** Текст, який бачить користувач застосунку (UI-контент), лишається українською.
- **Комітити не після кожної дрібної правки** — робити один коміт на завершений раунд фідбеку/задачу (за замовчуванням: один коміт = одна гілка = один PR), а не окремий коміт на кожен маленький твік. Комітити тільки коли користувач явно каже, що готово.
- Користувач свідомо обрав **повну функціональність** (не спрощену версію) і готовий поступово вчити складніші речі.

### Git-процес (усталений, повторювати без пояснень)
`git checkout main && git pull` → нова гілка (`feature/...`) → робота → `git commit` (англійською) → `git push` → Pull Request на github.com (немає `gh` CLI, тому через сайт) → "Merge pull request" → Claude перевіряє, що merge пройшов без конфліктів і що `main` працює → `git checkout main && git pull` → видалити стару гілку (локально і на GitHub).

Уже пройдено так: `feature/landing-page` → `feature/dashboard` → `feature/extended-notes` → `feature/rename-branding` → `feature/glossary-sort` → `feature/glossary-review-tracking` → `feature/calendar-fixes` → `feature/calendar-size-style` → `feature/theme-colors` → `feature/landing-home` → `feature/dashboard-fixes` → `feature/login-redesign` (усі змержені в `main`). Зараз в роботі `feature/remember-me` ("Запам'ятати мене" + спрощена форма входу для тих, хто вже реєструвався раніше).

## Структура файлів проекту

Проект розділено по папках (фронтенд/бекенд, і всередині фронтенду — сторінки/стилі/скрипти/картинки окремо), сервер віддає сторінки через явні маршрути (`/`, `/login`, `/dashboard`), а не напряму по `.html`-іменах:

```
pages/
  index.html      — головна/лендінг сторінка (лого, заголовок, "Увійти"/"Реєстрація" → /login)
  login.html      — форма входу/реєстрації (email → код підтвердження), темна тема
  dashboard.html  — кабінет: бічна панель + розділи (Огляд/Нотатки/Глосарій/Календар/Профіль)
public/
  css/
    styles.css     — БІЛЬШЕ НЕ ВИКОРИСТОВУЄТЬСЯ (стара світла тема login.html, замінена на login.css; кандидат на видалення)
    landing.css    — стилі index.html (темна тема)
    dashboard.css  — стилі кабінету (темна тема, чорно-біло-сіра)
    login.css      — стилі login.html (темна тема, узгоджена з landing.css/dashboard.css)
  js/
    script.js      — логіка login.html (валідація, код, таймер, "запам'ятати мене", режим спрощеного входу)
    home.js        — логіка index.html (мовний перемикач з localStorage, FAQ-акордеон, scroll-reveal, скрол на верх по лого)
    dashboard.js    — логіка кабінету (нотатки, глосарій, календар, профіль) — великий файл
  imgs/
    favicon.svg, logo.svg         — старе лого (три гори), більше ніде не використовується
    favicon-white.svg, logo-white.svg — нове лого (біле, стовпчики) — використовують dashboard.html, index.html і login.html
server/
  server.js       — Express-сервер: роздає public/ як статику, маршрути /, /login, /dashboard, /request-code, /verify-code
package.json, package-lock.json, node_modules/ (в .gitignore)
```

## Що вже готово

**Головна сторінка (`pages/index.html`)** — повністю передизайнована, темна тема, узгоджена з кабінетом:
- Шапка: нове біле лого (з текстом), посилання "Можливості"/"Чому ми"/FAQ (скрол до відповідної секції, з відступом під sticky-шапку), "Увійти" (→ `/login?mode=login`) / "Реєстрація" (→ `/login`), мовний перемикач UA/EN (сегментований контрол, лише візуально — без реального перекладу, але вибір зберігається в `localStorage` і відновлюється при заході)
- Hero: заголовок, підпис, кнопки "Почати безкоштовно"/"Переглянути можливості", плаваючі картки-приклади продукту (декоративні, `aria-hidden`)
- Секції "Можливості" (4 картки), "Чому ми" (3 пункти), FAQ (5 питань, акордеон на чистому JS з плавною анімацією висоти, світінням бордера при відкритті, іконка плюс↔хрест), фінальний CTA-блок, футер
- Повна адаптивність, перевірено й виправлено в діапазоні 320px–1920px
- Семантика: `<main>` навколо основного контенту, один `<h1>`, ARIA на FAQ-акордеоні і мовному перемикачі, декоративні іконки/блоки — `aria-hidden`
- Стилі — окремий файл `public/css/landing.css`

**Вхід/реєстрація (`pages/login.html`)** — повністю передизайнована під темну тему (гілка `feature/login-redesign`), той самий візуальний стиль, що на головній і в кабінеті:
- Картка з glow-фоном, нове біле лого, заголовок "Увійти в акаунт"
- Поле "Ім'я користувача" (над Email) + поле Email, обидва з хрестиком-очищенням (SVG-іконка, збільшується й обертається на 90° при наведенні — той самий патерн, що і на кнопках закриття в кабінеті), обидва валідуються при сабміті
- Enter у полі імені переводить фокус на Email замість сабміту форми
- `autocomplete="off"` на полі імені — прибирає підказку Chrome про збережений акаунт/профіль
- Чекбокс "Запам'ятати мене" під полем Email
- Код підтвердження — реальна перевірка через сервер (`/request-code`, `/verify-code`), таймер на повторну відправку (30с, світліший текст для контрасту на сірому фоні), toast-сповіщення при відправці/повторній відправці коду
- Реальний редирект на `/dashboard` після успішного коду (раніше був `alert`)
- Ім'я/email при успішному вході зберігаються в той самий `localStorage` (`notaAppState`), який читає кабінет — не перезаписуючи інші дані користувача (списки, глосарій, події), і не затираючи вже збережене ім'я, якщо поточна форма його не запитувала (див. нижче про спрощену форму)
- "Назад" — посилання на головну, всередині картки (верхній лівий кут)
- Мовний перемикач — той самий сегментований UA/EN тумблер, що на головній (не dropdown із глобусом), синхронізований через `localStorage` (`notaLang`)
- **"Запам'ятати мене":** якщо позначено і код підтверджено — мітка часу (10 днів) в `localStorage` (`notaRememberedUntil`). Поки вона дійсна, заход на `/login` одразу редиректить на `/dashboard`, форма навіть не встигає показатись (перевірка — вбудований `<script>` у `<head>`, до рендеру body)
- **Спрощена форма входу:** якщо користувач вже логінився раніше на цьому браузері (`localStorage.notaHasLoggedInBefore`) і клікнув саме "Увійти" (`/login?mode=login`) — форма ховає поле імені й чекбокс "Запам'ятати мене", кнопка каже "Продовжити" замість "Створити акаунт". Якщо він ще ніколи не реєструвався — і "Увійти", і "Реєстрація" показують однакову повну форму. "Реєстрація" завжди показує повну форму, незалежно від історії
- Стилі — окремий файл `public/css/login.css`, `styles.css` більше ніде не використовується

**Кабінет (`pages/dashboard.html`)** — чорно-біло-сіра тема "Notes Planner", розділи:
- **Огляд** — статистика, план на сьогодні, прогрес списків (градієнт сіро-білий)
- **Нотатки** — кілька окремих списків з повним CRUD, видалення списку прямо з сайдбару (кошик при наведенні, з підтвердженням), активний список у сайдбарі пульсує білою крапкою. Усі дії оновлюють DOM точково, без перемальовування всього списку. Кнопка "Додати" з порожнім полем ставить фокус у поле вводу. Є "компактний режим" (керується з Профілю)
- **Глосарій** ("розширені нотатки") — терміни з rich-text поясненням, категорії з кастомними кольорами, пріоритет, галерея зображень, пошук + фільтр за категорією, сортування, відстеження "вивчив/не вивчив" з прогрес-баром, режим "Повторення термінів" (флешкартки), підтвердження видалення терміна. HTML-пояснення санітизується (захист від XSS)
- **Календар** — місячна сітка з динамічною кількістю рядків, анімоване перемикання місяців, модалка "День" зі списком подій, компактна модалка перегляду події, форма редагування (назва, дата, час зі степером, тип з автопідказками, локація, нотатка, нагадування — поле зберігається, відправка на email ще не підключена)
- **Профіль** — ім'я/email, завантаження фото, "Показувати підказки" і "Компактний режим" реально працюють; сповіщення/тема/мова — тумблери є, але поки без реальної дії
- **Лого в сайдбарі** веде на головну сторінку (`href="/"`, раніше було `href="#"`)
- **Кнопка "+ Список" в шапці** — прибрана з Огляду й Профілю (дублювала постійну кнопку в сайдбарі), лишилась тільки для Нотаток/Глосарія/Календаря, де це єдиний швидкий спосіб додати. На вузьких екранах зменшується, а на зовсім вузьких (≤420px) лишає тільки іконку

**Дані зберігаються в `localStorage`** — списки, нотатки, глосарій, події, профіль і налаштування переживають перезавантаження сторінки.

**Бекенд (`server/server.js`)** — Express, явні маршрути `/`, `/login`, `/dashboard` + `/request-code`, `/verify-code` (код у пам'яті сервера, скидається при перезапуску — це нормально для поточного етапу).

**Адаптивність** — Глосарій, головна сторінка і сторінка входу повністю перевірені й адаптовані під мобільні (320px–1920px). Решта кабінету (Нотатки/Календар/Профіль/Огляд) — ще ні.

**Плавний скрол** — `scroll-behavior:smooth` підключено по всьому кабінету і на головній сторінці.

## Що тимчасове або неповне (важливо пам'ятати)

1. **Дані в `localStorage`, не в справжній базі даних.** SQLite заплановано, ще не підключено — дані не синхронізуються між пристроями/браузерами.
2. **Email не надсилається насправді** — код входу виводиться в термінал сервера (`console.log`). Поле "Нагадування" в події календаря так само поки тільки зберігає обраний час — чекає на той самий етап (SQLite + сервіс email).
3. **Профіль → Налаштування** — "сповіщення", тема, мова досі без реальної дії ("підказки" і "компактний режим" уже працюють).
4. **Аутентифікація і дані не пов'язані.** Нотатки/списки/глосарій не прив'язані до конкретного залогіненого email — все на одному спільному `localStorage` браузера.
5. **Адаптивність решти кабінету** (Нотатки/Календар/Профіль/Огляд, не Глосарій) під мобільні — не перевірялась спеціально.
6. **`styles.css`** — тепер взагалі не використовується жодною сторінкою (був тільки для старого `login.html`), кандидат на видалення.
7. **"Запам'ятати мене" — тимчасова, несправжня реалізація.** Це просто мітка часу в `localStorage` браузера, а не серверна сесія/токен — будь-хто може обійти це через DevTools. Замінити на справжню серверну сесію треба разом із пунктом 1-2 плану (SQLite + акаунти).

## План дій (наступні кроки, по порядку)

1. Підключити справжню базу даних (SQLite) — замість `localStorage`.
2. Зв'язати нотатки/списки/глосарій/події з конкретним залогіненим користувачем; замінити клієнтське "Запам'ятати мене" на справжню серверну сесію.
3. Реальна відправка email (Resend чи подібне) — і для коду входу, і для нагадувань з календаря.
4. Темна/світла тема — зробити перемикач функціональним.
5. Повне перемикання мов (UA/EN).
6. Перевірити й доробити адаптивність решти кабінету під мобільні екрани (Нотатки/Календар/Профіль/Огляд).
7. Видалити `styles.css` і за потреби уніфікувати `dashboard.css`/`landing.css`/`login.css`.
8. (Опційно, в кінці) Деплой сайту на хостинг.
