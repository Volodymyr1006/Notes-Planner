# Notes Planner — стан проекту (для нового чату з Claude)

Це файл-довідка, щоб продовжити роботу над проектом у новій розмові з Claude без втрати контексту. Встав посилання на цей файл або скопіюй його вміст на початку нового чату.

## Що це за проект

Особистий застосунок для нотаток і планування подій у календарі. Перший повноцінний проект користувача "з нуля" — навчальний, робиться крок за кроком.

- **Користувач:** новачок, вчить фронтенд/бекенд вперше. Знає HTML/CSS/JS-основи, вивчає складніші речі (JS backend, DOM-маніпуляції, git) поступово, крок за кроком, у процесі побудови цього проекту.
- **GitHub:** `Volodymyr1006/Notes-Planner` (приватний репозиторій)
- **Стек:** чистий HTML/CSS/JS (без фреймворків) на фронтенді, Node.js + Express на бекенді. Дані поки зберігаються в `localStorage` браузера (SQLite заплановано, ще не підключено).

## Як ми працюємо (важливо для нового чату!)

- **Пояснення прості, короткі, покроково.** Не перевантажувати текстом.
- **Нова функціональність (нові сторінки/фічі):** Claude веде, пропонує наступний крок, користувач підтверджує/виконує.
- **Стилізація вже готового:** користувач каже що саме змінити, Claude робить.
- **JS користувач пише сам** невеликими шматками для нового навчального матеріалу — Claude дає код + пояснення. Але коли йдеться про адаптацію готового макету/дизайну (як було з переробкою кабінету і Глосарієм) — Claude пише код повністю сам, це окремий режим роботи, не суперечить попередньому пункту.
- **Формат пояснення JS-коду:** розбір по частинах, коротко на кожен рядок/елемент, і показати відповідний фрагмент HTML.
- **Перед новим складним поняттям** — питати, чи пояснювати, чи одразу писати код.
- **Не забігати наперед:** не починати наступне завдання чи ставити уточнювальні питання про нього одразу після завершення поточного — чекати, поки користувач сам підніме тему.
- Користувач свідомо обрав **повну функціональність** (не спрощену версію) і готовий поступово вчити складніші речі.

### Git-процес (усталений, повторювати без пояснень)
`git checkout main && git pull` → нова гілка (`feature/...`) → робота → `git commit` → `git push` → Pull Request на github.com (немає `gh` CLI, тому через сайт) → "Merge pull request" → Claude перевіряє, що merge пройшов без конфліктів і що `main` працює → `git checkout main && git pull` → видалити стару гілку (локально і на GitHub).

Уже пройдено так: `feature/landing-page` → `feature/dashboard` → `feature/extended-notes` → `feature/rename-branding` → `feature/glossary-sort` → `feature/glossary-review-tracking` → `feature/calendar-fixes` → `feature/calendar-size-style` → `feature/theme-colors` (усі змержені в `main`). Зараз в роботі `feature/landing-home` (повний редизайн головної сторінки).

## Структура файлів проекту

Проект розділено по папках (фронтенд/бекенд, і всередині фронтенду — сторінки/стилі/скрипти/картинки окремо), сервер віддає сторінки через явні маршрути (`/`, `/login`, `/dashboard`), а не напряму по `.html`-іменах:

```
pages/
  index.html      — головна/лендінг сторінка (лого, заголовок, кнопка "Реєстрація" → /login)
  login.html      — форма входу (email → код підтвердження, з таймером на повторну відправку)
  dashboard.html  — кабінет: бічна панель + розділи (Огляд/Нотатки/Глосарій/Календар/Профіль)
public/
  css/
    styles.css     — стилі login.html (світла тема, стара; index.html більше її НЕ використовує)
    landing.css    — стилі index.html (нова темна тема, окремий файл від styles.css)
    dashboard.css  — стилі кабінету (темна тема, чорно-біло-сіра)
  js/
    script.js      — логіка login.html (валідація email, код, таймер)
    home.js        — логіка index.html (мовний перемикач з localStorage, FAQ-акордеон, scroll-reveal, скрол на верх по лого)
    dashboard.js    — логіка кабінету (нотатки, глосарій, календар, профіль) — великий файл
  imgs/
    favicon.svg, logo.svg         — старе лого (три гори) — досі використовує login.html
    favicon-white.svg, logo-white.svg — нове лого (біле, стовпчики) — використовують dashboard.html і index.html
server/
  server.js       — Express-сервер: роздає public/ як статику, маршрути /, /login, /dashboard, /request-code, /verify-code
package.json, package-lock.json, node_modules/ (в .gitignore)
```

## Що вже готово

**Головна сторінка (`pages/index.html`)** — повністю передизайнена (гілка `feature/landing-home`), темна тема, узгоджена з кабінетом:
- Шапка: нове біле лого (з текстом), посилання "Можливості"/"Чому ми"/FAQ (скрол до відповідної секції, з відступом під sticky-шапку), "Увійти"/"Реєстрація" → `/login`, мовний перемикач UA/EN (сегментований контрол, лише візуально — без реального перекладу, але вибір зберігається в `localStorage` і відновлюється при заході)
- Hero: заголовок, підпис, кнопки "Почати безкоштовно"/"Переглянути можливості", плаваючі картки-приклади продукту (декоративні, `aria-hidden`)
- Секції "Можливості" (4 картки), "Чому ми" (3 пункти), **FAQ** (5 питань, акордеон на чистому JS з плавною анімацією висоти, світінням бордера при відкритті, іконка плюс↔хрест), фінальний CTA-блок, футер
- **Повна адаптивність**, перевірено й виправлено в діапазоні 320px–1920px: на вузьких екранах лого звужується до іконки (+ короткий напис, якщо влазить), мовний перемикач стає компактною кнопкою-глобусом з випадаючим меню, уся типографіка/відступи/розміри кнопок масштабуються під мобільний (а не залишаються desktop-розміром), декоративний hero-блок з картками ховається на вузьких екранах
- Семантика: `<main>` навколо основного контенту, один `<h1>`, ARIA на FAQ-акордеоні (`aria-expanded`/`aria-controls`) і мовному перемикачі (`role="group"`, `aria-pressed"`), декоративні іконки/блоки — `aria-hidden`
- Стилі — окремий файл `public/css/landing.css` (не `styles.css`, який лишився тільки для `login.html`)

**Вхід (`pages/login.html`)**
- Email з валідацією, код генерується/перевіряється на сервері через `/request-code`/`/verify-code`
- Хрестик "змінити email" (з плавним поворотом на 90° при наведенні), кнопка "Надіслати повторно" з таймером

**Кабінет (`pages/dashboard.html`)** — чорно-біло-сіра тема "Notes Planner" (перефарбовано з фіолетового акценту, гілка `feature/theme-colors`), розділи:
- **Огляд** — статистика, план на сьогодні, прогрес списків (градієнт сіро-білий)
- **Нотатки** — кілька окремих списків з повним CRUD, видалення списку прямо з сайдбару (кошик при наведенні, з підтвердженням), активний список у сайдбарі пульсує білою крапкою. Усі дії (позначити виконаним, додати, видалити пункт) оновлюють DOM точково, без перемальовування всього списку — нічого не "блимає". Кнопка "Додати" з порожнім полем просто ставить фокус у поле вводу замість того, щоб нічого не робити. Є "компактний режим" (менші відступи, керується з Профілю — див. нижче).
- **Глосарій** ("розширені нотатки") — терміни з rich-text поясненням (жирний/підкреслення/маркер-виділення — тепер одним приглушеним кольором по кліку, без попапу вибору кольору/копіювання виділеного тексту), категорії з кастомними кольорами (10 варіантів, вільний текстовий ввід з підказками), пріоритет (низький/середній/високий), галерея зображень (стиснення на клієнті перед збереженням, зміна розміру перетягуванням), пошук + фільтр за категорією, **сортування** (за замовчуванням / А-Я / Я-А, власний анімований випадаючий список), **відстеження "вивчив/не вивчив"** (чекбокс-галочка на кожній картці, прогрес-бар — загальний або в межах вибраної категорії, фільтр "Тільки невивчені", позначення прямо в режимі повторення), режим **"Повторення термінів"** (флешкартки з переворотом, клавіатурні стрілки ←/→ і Space/Enter, карусельний перехід між картками, кнопки "Ще вчу"/"Знаю"), підтвердження видалення терміна (два кліки, автоскидання через 5с). HTML-пояснення терміна санітизується (захист від XSS через contenteditable). Кольори категорій/пріоритету приглушені всюди (картки, бейджі, ліва смужка пріоритету) — колір лишається лише в маленькій крапці-акценті, щоб не рябіло.
- **Календар** — місячна сітка з динамічною кількістю рядків (4-6 залежно від місяця), клітинки сусідніх місяців порожні, клітинки з подіями підростають (обмежено одним рівнем, щоб не розтягувались надмірно), дні з 4+ подіями показують бейдж-лічильник замість обрізаного тексту, довгий текст події прокручується "біжучим рядком" при наведенні. **Перемикання місяців анімоване** (старий і новий місяць одночасно з'їжджають/заїжджають, без "блимання"). Клік на день відкриває модалку **"День"** зі списком подій; клік на подію відкриває **компактну модалку перегляду** (назва/час/тип/локація/нотатка, іконки редагувати/видалити) замість одразу повної форми. Форма редагування: назва, дата, час початку/кінця (степер ±5хв або ручний ввід), тип (вільний текст з автопідказками, колір як у категорій Глосарія), локація, нотатка, нагадування (поле зберігається, відправка на email ще не підключена). Кольори типів подій так само приглушені (мітка зліва в списках подій, фон міні-подій у сітці).
- **Профіль** — ім'я/email, завантаження фото (стиснення на клієнті), налаштування: **"Показувати підказки" і "Компактний режим" — тепер реально працюють** (підказки в порожніх станах, стиснутий вигляд списку нотаток; застосовуються одразу і зберігаються в `localStorage`), сповіщення/тема/мова — тумблери є, але поки без реальної дії. Стан тумблерів тепер коректно відновлюється при перезавантаженні сторінки (раніше показував дефолт незалежно від збереженого значення).

**Дані зберігаються в `localStorage`** — списки, нотатки, глосарій, події, профіль і налаштування переживають перезавантаження сторінки.

**Бекенд (`server/server.js`)** — Express, явні маршрути `/`, `/login`, `/dashboard` + `/request-code`, `/verify-code` (код у пам'яті сервера, скидається при перезапуску — це нормально для поточного етапу).

**Адаптивність** — Глосарій у кабінеті цілком перевірено й виправлено під мобільний екран (375px), включно з плаваючою панеллю форматування. Головна сторінка (`index.html`) повністю перевірена й адаптована в діапазоні 320px–1920px (див. вище). Решта кабінету (Нотатки/Календар/Профіль/Огляд) — ще ні.

**Плавний скрол** — `scroll-behavior:smooth` підключено по всьому кабінету (і на головній сторінці) для якірних переходів/фокусу.

## Що тимчасове або неповне (важливо пам'ятати)

1. **Дані в `localStorage`, не в справжній базі даних.** SQLite заплановано, ще не підключено — дані не синхронізуються між пристроями/браузерами.
2. **Email не надсилається насправді** — код входу виводиться в термінал сервера (`console.log`). Поле "Нагадування" в події календаря так само поки тільки зберігає обраний час, без фактичної відправки — це чекає на той самий етап (SQLite + сервіс email), бо для нагадувань за розкладом потрібен сервер, що знає про дані користувача і вміє надсилати листи.
3. **Профіль → Налаштування** — "сповіщення", тема, мова досі без реальної дії за собою ("підказки" і "компактний режим" уже працюють, див. вище).
4. **`login.html` відстає від нового дизайну** — досі стара світла тема (`styles.css`) і старе лого (три гори), поки `index.html` і `dashboard.html` уже на новій чорно-білій темі з новим лого. Свідомо відкладено.
5. **Аутентифікація і дані не пов'язані.** Нотатки/списки/глосарій не прив'язані до конкретного залогіненого email.
6. **Адаптивність решти кабінету** (Нотатки/Календар/Профіль/Огляд, не Глосарій) під мобільні — не перевірялась спеціально. Головна сторінка (`index.html`) — уже перевірена.
7. **`styles.css`** (тепер лише для `login.html`, світла тема) і **`dashboard.css`**/**`landing.css`** (темна тема) — три окремі файли з різними палітрами, не уніфіковані.

## План дій (наступні кроки, по порядку)

1. Підключити справжню базу даних (SQLite) — замість `localStorage`.
2. Зв'язати нотатки/списки/глосарій/події з конкретним залогіненим користувачем.
3. Реальна відправка email (Resend чи подібне) — і для коду входу, і для нагадувань з календаря.
4. Темна/світла тема — зробити перемикач функціональним.
5. Повне перемикання мов (UA/EN).
6. Оновити `login.html` під нову чорно-білу тему й нове лого (наздогнати index.html/dashboard.html).
7. Перевірити й доробити адаптивність решти кабінету під мобільні екрани (Нотатки/Календар/Профіль/Огляд — головну сторінку вже зроблено).
8. Уніфікувати/розділити стилі (`styles.css` + `dashboard.css` + `landing.css`).
9. (Опційно, в кінці) Деплой сайту на хостинг.
