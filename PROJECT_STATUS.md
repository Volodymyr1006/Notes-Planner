# Notes Planner — стан проекту (для нового чату з Claude)

Це файл-довідка, щоб продовжити роботу над проектом у новій розмові з Claude без втрати контексту. Встав посилання на цей файл або скопіюй його вміст на початку нового чату.

## Що це за проект

Особистий застосунок для нотаток і планування подій у календарі. Перший повноцінний проект користувача "з нуля" — навчальний, робиться крок за кроком.

- **Користувач:** новачок, вчить фронтенд/бекенд вперше. Знає HTML/CSS/JS-основи, вивчає складніші речі (JS backend, DOM-маніпуляції, git) поступово, крок за кроком, у процесі побудови цього проекту.
- **GitHub:** `Volodymyr1006/Notes-Planner` (приватний репозиторій)
- **Стек:** чистий HTML/CSS/JS (без фреймворків) на фронтенді, Node.js + Express на бекенді. База даних ще не підключена (заплановано SQLite).

## Як ми працюємо (важливо для нового чату!)

- **Пояснення прості, короткі, покроково.** Не перевантажувати текстом.
- **Нова функціональність (нові сторінки/фічі):** Claude веде, пропонує наступний крок, користувач підтверджує/виконує.
- **Стилізація вже готового:** користувач каже що саме змінити, Claude робить.
- **JS користувач пише сам**, невеликими шматками — Claude дає код + пояснення, користувач вставляє у файл сам і каже "додав". HTML/CSS Claude редагує напряму сам.
- **Формат пояснення JS-коду:** розбір по частинах, коротко на кожен рядок/елемент ("`const` — створили змінну", "`document.querySelector('...')` — дістали елемент" і т.д.), і показати відповідний фрагмент HTML, щоб було видно реальний елемент, а не уявляти його з тексту.
- **Перед новим складним поняттям** (нове ключове слово JS, новий підхід) — питати, чи пояснювати, чи одразу писати код.
- Користувач свідомо обрав **повну функціональність** (не спрощену версію) і готовий поступово вчити складніші речі (стрілкові функції, масиви, contenteditable тощо) — не уникати складності, а пояснювати її крок за кроком.

## Структура файлів проекту

```
index.html      — головна/лендінг сторінка (лого, заголовок, кнопка "Реєстрація" → login.html)
login.html      — форма входу (email → код підтвердження, з таймером на повторну відправку)
dashboard.html  — кабінет: бічна панель + розділи (Огляд/Профіль/Календар/Нотатки)
styles.css      — усі стилі одним файлом (уже великий, план розділити пізніше)
script.js       — логіка login.html (валідація email, код, таймер)
home.js         — логіка index.html (тільки перемикач мови)
dashboard.js    — логіка dashboard.html (перемикання розділів, створення списків нотаток)
server.js       — Express-сервер (роздає сайт + /request-code, /verify-code)
imgs/           — favicon.svg, logo.svg (лого — три гори)
package.json, package-lock.json, node_modules/ (в .gitignore)
```

## Що вже готово

**Головна сторінка (`index.html`)** — лого, заголовок, кнопка "Реєстрація" → `login.html`, посилання "Увійти", мовна кнопка (UA/EN, поки без реального перекладу).

**Вхід (`login.html`)**
- Поле email з валідацією (порожнє / некоректний формат)
- Після правильного email: поле стає `readonly`, з'являється хрестик "змінити email", плавно випливає поле для коду підтвердження
- Код генерується і перевіряється **на сервері** (не в браузері — це свідомо зроблено для безпеки), через `fetch()` на `/request-code` і `/verify-code`
- Кнопка "Надіслати повторно" з відліком 30 секунд
- Мовна кнопка (візуально готова, перемикання мови ще не реалізоване)
- Базова семантика/доступність: `lang="uk"`, `meta description`, `aria-*` атрибути, `role="alert"` на помилках

**Кабінет (`dashboard.html`)**
- Бічна панель: лого, пошук (поки не працює), меню (Огляд/Профіль/Календар/Нотатки), кнопка "+ Новий список", список "Мої списки"
- Клік по пунктах меню плавно перемикає розділи справа (fade-перехід)
- "+ Новий список" створює новий пункт зліва з можливістю одразу вписати назву (contenteditable, Enter підтверджує)
- Клік по будь-якому пункту списку показує розділ "Нотатки" (поки що **завжди той самий** порожній стан — списки ще не розрізняються між собою, це наступний крок)
- "Порожній стан" зроблений і для основного вмісту ("Список порожній"), і для бічної панелі ("Немає списків"), коли списків нема
- Розділи "Календар" і "Профіль" — поки просто заглушки

**Бекенд (`server.js`)**
- Express-сервер, роздає весь сайт (`express.static`)
- `/request-code` і `/verify-code` — генерують/перевіряють код підтвердження, зберігають у **пам'яті сервера** (об'єкт `verificationCodes`, не база даних — скидається при перезапуску сервера, це нормально для поточного етапу)

## Що тимчасове або неповне (важливо пам'ятати)

1. **Нема бази даних.** Усі нотатки/списки живуть тільки в браузері (в DOM), зникають при оновленні сторінки. Це не "тестовий код для видалення" — це основа, яку розширимо (додамо збереження), а не перепишемо з нуля.
2. **Списки нотаток ще не розрізняються.** Усі пункти в "Мої списки" ведуть на той самий (поки порожній) розділ "Нотатки" — нема прив'язки даних до конкретного списку. Це наступний запланований крок.
3. **Email не надсилається насправді** — код виводиться в термінал сервера (`console.log`). Реальна відправка (наприклад через Resend) запланована на кінець, разом з іншими "фінальними штрихами".
4. **Профіль і Календар** — тільки візуальні заглушки, без реальної логіки.
5. **Мовний перемикач (UA/EN) і темна тема** — тільки візуальні елементи, без реального перемикання. Заплановано на кінець.
6. **`styles.css` розрісся** (три сторінки в одному файлі) — заплановано розділити на `base.css` + окремі файли по сторінках (не по дрібних компонентах).
7. **Адаптивність кабінету під мобільні екрани** не перевірялась після останньої переробки бічної панелі (пошук + список).

## План дій (наступні кроки, по порядку)

1. **Дані для списків нотаток.** Зробити так, щоб кожен список (в "Мої списки") зберігав **свої власні** нотатки окремо від інших — зараз усі ведуть в один спільний (порожній) розділ.
2. **Повний CRUD нотаток всередині списку:** додавання (частково є в HTML/CSS), позначення виконаним, видалення, відображення прогресу (X з Y виконано).
3. **Календар:** вигляд місяця, додавання подій з датою/часом, збір дат нотаток з усіх списків в одному місці (як обговорювали).
4. **Підключити справжню базу даних (SQLite).** Зберігати списки, нотатки, події — щоб нічого не зникало при оновленні сторінки.
5. **Зв'язати нотатки/списки з конкретним залогіненим користувачем** (зараз аутентифікація і нотатки — не пов'язані між собою).
6. **Реальна відправка email** (замість `console.log`) — окремий сервіс типу Resend.
7. **Розділити `styles.css`** на `base.css` + сторінкові файли.
8. **Темна/світла тема** — зробити перемикач функціональним.
9. **Повне перемикання мов** (UA/EN) — реальний переклад інтерфейсу.
10. Перевірити й доробити адаптивність кабінету під мобільні екрани.
11. (Опційно, в кінці) Деплой сайту на хостинг.

## Найближчий крок прямо зараз

Пункт 1 з плану вище: навчити `dashboard.js` розрізняти, які нотатки належать якому списку (замість того, щоб усі списки показували один спільний порожній розділ "Нотатки"). Це вимагає простої структури даних (масив об'єктів "список → його нотатки") і функції рендеру, яка перемальовує вміст залежно від того, який список обрано.
